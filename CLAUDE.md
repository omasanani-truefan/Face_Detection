# FaceTrack: notes for Claude Code

Lightweight face detection and temporary multi-face tracking (Phases 1-2; recognition is Phase 3 and
not implemented). Python reference in `src/facetrack`, browser app in `web/`, benchmarks in `scripts/`.
Start with `README.md` ("Start here") and `BENCHMARK.md`.

## If the user asks you to set this up or get it running

Work through these in order and stop at the first failure; fix it, then continue.

1. `python scripts/check_setup.py` shows what is missing and how to fix it. Re-run it after each fix.
2. Environment: Python 3.10+, a virtualenv, then `python -m pip install --upgrade pip` (Python 3.10's
   bundled pip cannot do the editable install), then `pip install -e ".[mediapipe,bench,youtube,report,dev]"`.
3. `python scripts/download_models.py` (small models, checksum-verified).
4. `pytest -q` should pass (detector tests that need the WIDER FACE dataset skip themselves).
5. Demo: `facetrack-demo --url "<youtube link>"` (streams, nothing is saved) or `--video file.mp4`.
6. Browser app: `cd web && npm install && npm run dev`, paste a YouTube link in "Uploaded video".
   `npm run build` type-checks; `npm test` checks the TypeScript tracker against the Python one.
7. Benchmark (only if asked): `python scripts/download_suggested_models.py`, then
   `python scripts/bench_youtube.py URL_A URL_B`, then `python scripts/build_benchmark_report.py`.

"Working" means: `check_setup.py` says READY, tests pass, and the demo shows boxes with stable track IDs.

## Known problems and their fixes

* **YouTube says "Sign in to confirm you're not a bot".** A network-address rate limit, not a bug. Ask the
  user before using their browser login, then set `FACETRACK_YT_COOKIES_BROWSER=chrome` (or firefox,
  edge) or `FACETRACK_YT_COOKIES_FILE`, and re-run. Set it before `npm run dev` for the browser app.
  Local video files and the camera are unaffected. Do not keep retrying lookups in a loop.
* **Browser YouTube box says "needs the local dev server".** It only works under `npm run dev` or
  `npm run preview`, and needs yt-dlp in the Python environment (`pip install -e ".[youtube]"`);
  set `FACETRACK_PYTHON` if the venv is elsewhere.
* **A video will not play in the browser.** The codec is probably not H.264/VP9/AV1; transcode with
  `imageio-ffmpeg`. The app reports this itself.
* **mediapipe fails to install.** It is optional; skip the `mediapipe` extra and avoid the BlazeFace detectors.

## Rules for this repo

* Never commit `data/`, `models/*`, `results/demo/`, cookies, or frames from third-party videos
  (`.gitignore` covers them). Do not save YouTube videos to disk; they are streamed only.
* Do not hand-edit benchmark numbers. `BENCHMARK.md` and `docs/BENCHMARK_REPORT.*` are generated by
  `scripts/build_benchmark_report.py` from `results/youtube/summary.json`. Re-running a benchmark
  overwrites that file; timings differ per machine, so run on an idle, plugged-in computer and say so.
* Keep measured, proxy and estimated numbers separate in anything written. The YouTube "agreement" figures
  are a proxy (no human labels), not accuracy.
* A Track ID is not a Person ID. Do not add face recognition or ArcFace to Phases 1-2.
* Licences: SORT reference code is GPL-3.0 (not used here); InsightFace weights (SCRFD, ArcFace) are
  non-commercial; WIDER FACE is CC BY-NC-ND. See README and `docs/REPORT.md` section 10.
* Detector, tracker and frame source are separate modules behind small interfaces (`detectors/base.py`,
  `tracking/base.py`, `sources.py`); keep them replaceable. The browser tracker must match the Python one
  (`npm test`).
* Do not push, force-push or change git config unless the user asks.
